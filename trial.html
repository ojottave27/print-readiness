1. Already built and verified

Devanagari, end to end

uharfbuzz does the shaping using the font's GSUB/GPOS tables; fontTools converts each glyph to outlines. The SVG carries paths, never <text>, so the output does not depend on the reader having the font installed. PNG uses skia-python with the glyphs already shaped.

क्षेत्र   क्रम   पहाड़   मीटर   सेमी

Evidence, not a claim: क्षेत्र (7 characters) produces 3 glyphs, including uni0915094D0937 and uni0924094D0930. The 094D is the virama — the signature of a real ligature. क्रम produces 2 glyphs. पहाड़ produces uni095C.

Byte-identical on repeat runs, for both SVG and PNG (equal sha256). MIT/BSD dependencies only: uharfbuzz, fontTools, skia-python, Pillow, and Noto Serif Devanagari under the SIL OFL. No GPL or AGPL anywhere — PyMuPDF was discarded specifically because it is AGPL.

Figure 001 — three circles, solved by template

7 seconds, correct set hierarchy: each circle 7333 px², each pairwise intersection 2101 px², the triple 1668 px². A < AB < ABC holds, and the proportions are those of a real Venn rather than a collapsed one.

2. What this trial buys

Two things are not finished, and I would rather say so than be caught by them:

Generic label placement with clearance measured on real glyph outlines. My current 040 puts every number in the right region, but not always far enough from the lines. Region membership is not the same test as clearance, and I will not ship the first and call it the second.

Generic shape placement for mixed shapes. The three-circle case has a canonical configuration that scales. Four mixed shapes do not, and the general case is a constraint problem I have not finished solving.

Those are precisely the two risks that decide whether M1 is achievable. Three weeks on five figures of your choosing is a cheap way to find out, and it is money rather than a favour.

4. Figure 040 in JSON

The shape of the input the renderer takes. It states meaning only — no coordinates.

{
  "type": "venn.nonverbal",
  "lang": "en",
  "shapes": [
    {"id": "S", "kind": "circle", "label": "Student"},
    {"id": "D", "kind": "rect", "label": "Dancer"},
    {"id": "B", "kind": "rect", "label": "Boys"},
    {"id": "C", "kind": "triangle", "label": "Cricket player"}
  ],
  "regions": [
    {"in": ["S"], "value": [18]},
    {"in": ["S", "C"], "value": [2]},
    {"in": ["D"], "value": [6, 12]},
    {"in": ["D", "S"], "value": [5, 7]},
    {"in": ["D", "S", "C"], "value": [4]},
    {"in": ["D", "B"], "value": [10, 5]},
    {"in": ["D", "B", "S"], "value": [3, 6]},
    {"in": ["D", "B", "S", "C"], "value": [8]},
    {"in": ["B"], "value": [8, 12, 9]},
    {"in": ["B", "S", "C"], "value": [3, 2]},
    {"in": ["C"], "value": [3, 17]}
  ],
  "labels": "outside-with-leader"
}

The renderer decides where the shapes go, how large they are, and where inside each region the numbers fit.
